## **Machine Learning**
- Machine can learn new things
  
#### Types of Machine Learning
  - Supervised (training data has all the answers)
  - Unsupervised (anomaly detection)
  - Semisupervised (partially labelled, looking for patterns)
  - Reinforcement learning (getting towards AI...like training a dog with positive and negative rewards)

#### Modes
  - Batch learning (you get all the training data at once)
  - "Online" learning (system can accept new training data on the go)
  - Instance-based (commits training data to memory, then compares new data to training data)
  - Model-based (generalizes from a set of examples then uses that model to make predictions)

#### Problems...
  - Insufficient quantity of training data
  - Poor quality of training data
  - Non-representative training data

  - Transparent Training Practices?
  - Transparent Model Distribution?

# [*Coding After Coders* (Clive Thompson, NYT Magazine)](https://www.nytimes.com/2026/03/12/magazine/ai-coding-programming-jobs-claude-chatgpt.html)

## Core shift: coding → conversation
- Programming is shifting from **writing code → directing AI agents**.
- Developers use **natural language prompts** to specify intent.
- Work becomes **supervising, iterating, and correcting AI output**.

## Productivity explosion (with caveats)
- AI enables:
  - **10–100× speedups** in startups / greenfield projects
  - ~**10% gains** in large, complex organizations
- Tasks that took days/weeks now take **minutes/hours**.
- AI excels at:
  - Boilerplate generation
  - Testing
  - Debugging and codebase analysis

## New role of the programmer
- Developers become:
  - **Architects** (system design)
  - **Editors/judges** (evaluating output)
- Key skills shift toward:
  - Prompting
  - Decomposition
  - Verification
- Less emphasis on syntax, more on **intent + evaluation**

## Programming as abstraction (historical arc)
- Long trajectory:
  - Assembly → high-level languages → libraries → AI
- AI represents a new abstraction layer:
  - From writing instructions → **describing goals**
- Continues automation of “lower-level” work

## Why programmers are (mostly) excited
- AI removes:
  - Debugging drudgery
  - Repetitive tasks
- Leaves:
  - Design thinking
  - Experimentation
- Many developers feel:
  - More productive
  - More creative
  - More exploratory

## Programming becomes “deeply weird”
- Developers:
  - Argue with AI
  - Use emotional or exaggerated prompts
  - Treat models as semi-autonomous collaborators
- Coding becomes:
  - Conversational
  - Performative
  - Rhetorical

## Risks and tensions
- **Job disruption**
  - Decline in entry-level roles
  - Smaller teams required
- **Skill erosion**
  - Reduced deep coding ability for newcomers
- **Quality risks**
  - Potential for inefficient or bloated code
- **Labor dynamics**
  - AI as leverage against workers
- **Ethical concerns**
  - Training data, energy use, corporate control

## Uneven impact: startups vs big tech
- **Startups**
  - Near-total AI code generation
  - Massive productivity gains
- **Large companies**
  - Slower adoption
  - Focus on:
    - Reliability
    - Code review
    - Legacy systems

## Expansion of who can “code”
- Non-programmers can now:
  - Build working apps via prompting
- Rise of:
  - “Vibe coding”
- Blurs boundary between:
  - Developer ↔ user

## Economic uncertainty
- Two possibilities:
  - Fewer jobs (automation)
  - More jobs (increased demand — Jevons paradox)
- Open question:
  - Will productivity gains reduce or expand labor demand?

## Big conceptual takeaway
- Coding becomes:
  - Less about production
  - More about **judgment and systems thinking**
- Broader implication:
  - Many knowledge jobs may shift toward:
    - Prompting
    - Evaluating
    - Interpreting outputs
- “We will produce fewer first drafts and do more judging.”

# [*Death of a Software Developer* (Sarah Friend)](https://isthisanart.substack.com/p/death-of-a-software-developer)

## Core Argument
- The “software developer” is not just a job but a **cultural archetype and identity**, and that identity is now in decline.
- This decline is driven by **AI coding tools (e.g., Claude Code)** that reduce the need for traditional programming expertise.

## Identity vs Skill
- Becoming a developer historically meant **adopting a subcultural identity**, not just learning to code.
- This identity included:
  - Specific aesthetics (tools, books, habits)
  - Social signals (vim, Linux, esoteric knowledge)
- The author emphasizes **identity-based transformation** as key to entering the field.

## AI and the Shift in Software Production
- Many developers now say things like:
  - “I haven’t opened an IDE in months.”
- AI tools enable:
  - Faster production
  - Less need for deep technical understanding
- Result:
  - **Separation between “writing code” and “being a developer”**

## Jevons Paradox & Software Explosion
- Easier software creation → **more software overall**, not less.
- We are entering a **“software renaissance”**:
  - Massive increase in apps
  - Much of it low-quality or disposable
- Many people will use software **without understanding how it works**.

## Rise of the “Vibe Coder”
- New class of creators:
  - Use AI prompts to generate apps
  - Focus on outcomes, not technical mastery
- Key traits:
  - Do not seek traditional developer identity
  - Treat software like **content (e.g., Instagram posts)**
- Likely impacts:
  - Growth in low-stakes apps (SaaS, personal tools)
  - Collapse of parts of freelance/web dev economy

## Who Still Needs Traditional Developers
- Traditional developers persist in:
  - High-stakes systems
  - Enterprise environments
  - Security-critical contexts
- These roles require:
  - Accountability
  - Code review chains
  - Responsibility for failure

## Cultural Consequences
- Decline of the developer’s cultural dominance:
  - “Revenge of the Nerds” narrative fading
- Associated subcultures may decline:
  - Hacker aesthetics
  - Rationalist / effective altruist ideologies
- Possible shift toward:
  - More conventional status markers (fashion, office culture)

## Democratization of Software Creation
- New groups (previously excluded) will build tools:
  - Example: platforms like Ravelry (fiber arts community)
- Leads to:
  - **More diverse cultural production in software**
  - Expansion beyond traditional tech demographics

## Fragmentation of the Role
- Two diverging paths:
  1. **Traditional developer**
     - Deep expertise
     - Fewer people
     - Higher stakes
  2. **Vibe coder**
     - Broad participation
     - Low technical barrier
     - Rapid, disposable output

## Economic Implications
- Software jobs may still grow—but:
  - Value shifts downward for many roles
  - Entry-level pathways destabilized
- The “American Dream” of becoming a developer weakens.

## Final Perspective
- The future is not catastrophic, but **transformational**:
  - Software persists and expands
  - The developer becomes:
    - Less central culturally
    - More specialized professionally
- Identity becomes optional:
  - You can **make software without becoming a “software developer.”**
  
# Generative AI = Abstraction Layer Shift

## Core Shift
- Programming moves from **writing instructions** → **describing intentions**
- Code becomes **latent (machine-generated)** rather than fully explicit

## Coding → Conversation
Programming becomes:
- Prompting
- Iteration
- Evaluation

New developer roles:
- **Architect** — systems thinking
- **Editor** — judgment and refinement
- **Interrogator** — probing outputs

> Fewer first drafts, more judgment

## Productivity Reality
- **Startups:** 10–100× gains (speed, low constraints)
- **Large orgs:** ~10% gains (complexity bottlenecks)

AI excels at:
- Boilerplate
- Refactoring
- Testing
- Code navigation

AI struggles with:
- Architecture
- Maintainability
- Contextual judgment

## Labor Dynamics
Two futures:
- **Automation collapse:** fewer jobs, entry-level erosion
- **Jevons expansion:** more software → more demand

**Likely outcome:**
- Labor bifurcation:
  - Elite engineers (high-stakes systems)
  - “Vibe coders” (low-barrier, fast output)

## Role Fragmentation

**Path 1: Traditional Developer**
- Deep expertise
- Infrastructure, security
- Accountability

**Path 2: Vibe Coder**
- Broad access
- Fast, disposable output
- Lower technical barrier

## Structural Risks
- Skill erosion (especially beginners)
- Lower code quality
- Corporate consolidation of AI tools
- Opaque data/training practices

## Core Epistemic Shift

From:
- Knowing how to build systems

To:
- Knowing how to:
  - Ask
  - Judge
  - Interpret
